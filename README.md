# game-teardown

一个 Claude Code skill：把一款游戏拆成一份**经得起追问**的拆解案。

给它一个游戏名，它按六个设计域逐项追问、逼出判断，最后产出一份 6000–9000 字、
**每个数字都标了来源档位**的文档。品类无关——动作、射击、RPG、开放世界、卡牌、策略、
竞技、解谜、免费手游等十类都能跑。

成品见另一个仓库 → [`game-teardowns`](https://github.com/SueBerry0603/game-teardowns)

---

## 拆什么：六个设计域

正文**按设计域组织，不按用户的感受组织**——框架规定要拆什么，而不是让写的人想起什么写什么。

| 域 | 必答 | 必产 |
|---|---|---|
| 一 · 核心循环与节奏 | 三层循环（单次操作 / 单局 / 长线）、重心在哪层、时间轴、多久一次**有意义的决策**（不是操作） | 时间轴表 + 循环图 |
| 二 · 内容结构与关卡 | 划分与配比、硬门槛与保底、路径分支与**绕行成本**、崩盘点落在哪 | 结构表 + 结构图 |
| 三 · 数值与经济 | 结算结构（加算/乘算）、成长曲线 vs 压力曲线、资源产出与定价、阈值与溢出 | 数值表 2–5 |
| 四 · 系统与内容池 | 逐系统走：目标→规则→输入输出→反馈→失败惩罚→边界漏洞；内容池、元进度、商业化 | 内容池表 6–8 |
| 五 · 玩法机制 | 核心机制的经济：单次行动的收益与成本、可操作空间、信息透明度、上限与代价 | 机制表 9–10 |
| 六 · 反馈与表现 | 一次交互的反馈层级、信息层级、手感与可读性、教学与引导 | 截图 |

**每个域写三段，缺一段不算完成**：

- **事实** —— 数值表 / 规则 / 配比，一条一行，逐项标来源。**空着就是没拆。**
- **拆解** —— 现象 → 机制 → 设计意图 → 代价。机制必须落到数值上：
  ❌"那关太难"　✅"该关敌人有效血量 X、玩家期望输出 Y，需要 N 回合，超过这个数就没有容错空间"。
- **判断** —— 一句**可被反驳的话**，带内部基准、同品类外部对标、边界与证伪条件。

## 同一套域，八种口径

这是这套框架里最值得说的一处设计。「六域」不是一张固定的表——**同一套域在不同品类里要问的东西完全不同**。
所以开拆前先认领一行，域二与域五照它替换：

| 品类 | 域二看什么 | 数值单位 | 内容池 | 机制经济（域五） |
|---|---|---|---|---|
| 动作 / 射击 | 关卡节奏、遭遇战布局、检查点 | DPS、TTK、命中与暴击期望 | 武器 / 技能池 | 单次交火的输出与生存成本 |
| 平台 / 关卡制 | 关卡与教学曲线、难度坡 | 移动速度、容错窗口 | 关卡池、机制池 | 操作精度与容错帧 |
| RPG / 开放世界 | 区域与任务结构、引导与自由度 | 属性、等级曲线、装备强度 | 装备 / 任务 / 敌人池 | 资源回路（血/蓝/药/金币） |
| 卡牌 / 回合制 roguelike | 层与节点配比、路线成本 | 有效血量、每回合输出 | 卡池、事件池 | 能量与费效比 |
| 策略 / 模拟经营 | 关卡或剧本结构、阶段目标 | 产出与消耗速率、平衡比 | 单位 / 科技 / 建筑池 | 决策的收益与延迟 |
| 竞技 / 多人 | 地图与模式结构、匹配机制 | 平衡数值、胜率 | 英雄 / 装备池 | 信息与反应窗口 |
| 解谜 / 休闲 | 关卡与难度序列 | 步数 / 时间 / 容错 | 关卡池、机制池 | 信息充分性 |
| 免费手游 | 引导与留存节点、卡点设计 | 体力与钻石的产出/消耗 | 卡池与概率 | 付费与玩法的挂钩 |

## 怎么保证拆得对

上面那些是 v1 立起来的，产出的文档确实经得起追问——**但 v1 保证不了「生成得对」**。
一次实战里，一条结论「回归礼包只补了缺口的 **0.32%**」公式干净、来源齐全、**自检全过**，
**分母却选错了**：留住人的门槛不是补齐缺口，是够得着当期门槛。

v2 补了三件事：

- **写算式先问三个问题。** 分子分母各是什么 · **换一个合理的候选分母重算，结论会不会翻盘** ·
  能不能被复算。会翻盘 ＝ 分母是选出来的，不是算出来的。
- **收尾前跑一轮证伪。** 落完正文后扮演最强的对手：用一句话反驳每一处判断，反驳成立的就加固、
  降级或删掉；判负的改动在正文留痕。
- **推断要能被复算。** 每条推断配一份能一键重跑的脚本——换个人拿到仓库，只跑脚本就能复现正文里每一个数。

一句话：**v1 让我说不出含糊的话，v2 让我发现自己哪句话站不住。**

## 安装与使用

```bash
mkdir -p ~/.claude/skills/game-teardown
cp v2/SKILL.md ~/.claude/skills/game-teardown/SKILL.md
```

在 Claude Code 里说「拆解《某某》」或「写个拆解案」即可。产物落地位置分两种模式，skill 开工前自己判：
根目录有封面 README 的**索引仓库** → `<游戏-slug>/拆解案.md` 并加索引行；空目录的**独立仓库** → `README.md`。

## 它不做什么

- **不玩游戏。** 数值、系统规则、关卡结构由使用者提供——它负责追问、结构化、逼判断，不替人编数据。
- **不碰 git。** 上传是使用者的事。
- **不做批量采集任务。** 需要观察时最多布置 3 条带勾选字段与样本量的小任务，而不是让人逐场记录。
